# NRC SPA database layer

The database layer implements the SQLite contract in the root requirements. It requires SQLite 3.45+, stores one operational database on local disk, and exposes no network database service.

## Entry points

- Apply all pending migrations: `python -m database.migrate path/to/nrc_spa.db`
- Verify structure and integrity: `python -m database.verify path/to/nrc_spa.db`
- API integration: import `Database`, `ConcurrencyConflict`, and `draw_identifier` from `database`.

Every connection enables foreign keys, WAL, `synchronous=NORMAL`, a five-second busy timeout, and memory temporary storage. Every write uses `BEGIN IMMEDIATE`. API updates must supply the prior `row_version`; `Database.optimistic_update` increments it and reports stale writes.

UUIDs are canonical 36-character strings generated by the API. Timestamps are UTC ISO-8601 text. Money is an integer scaled by 10,000. Decimal result values are SQLite REAL values and must be range/precision validated by the API. Multi-select values and all documented many-to-many relations are normalized junction rows. Files remain in object storage; only their metadata and storage key are persisted.

SQLite cannot enforce row-level security. The API repository layer must append the documented user/team/business-unit privilege-depth predicate to every business query and fail closed when no request identity exists.

Open documentation decisions are deliberately not guessed: the Enterprise Risk computed-title formula, unresolved user-facing length choices, approval-chain depth policy, Risk Update contact/risk-lead defaults, and qualitative analytics fallback remain service/configuration decisions until OEDO resolves them.
